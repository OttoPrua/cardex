## 2. What the candidate does

`classifyGrokBuildProcessStderr` selects a closed process class (`transport`,
`permission_environment`, `invalid_invocation`, `unclassified`) from a bounded
window of the first 8 lines / 2048 bytes of stderr. Before the candidate, the
fail-closed check for stall diagnostics and JSON evidence ran *inside* that
window. Evidence past the bound was therefore invisible, and a stream whose first
lines looked like a clean transport failure could be typed as a terminal even
though later bytes proved the observation was not trustworthy.

`ac88fa9` moves that decision to `grokBuildProcessStderrHasFailClosedEvidence`,
which scans the **whole** stderr before any positive selection runs, and treats a
scanner error (a token past the 8 MiB bound) as evidence of loss rather than as
absence of evidence. The window survives only as the positive-selection bound.

When a class is selected, `invokeGrokBuild` replaces the result with
`exit_status=<n>` and narrows `combined` to stdout, and `runTaskVia` holds the
card on that class before the fallback and retry machinery can see it.

## 3. Independent proofs

Written in `grok_process_truth_independent_test.go` against the behaviour
contract, deliberately not reusing the candidate's fixtures or assertions, so a
defect in the candidate's own tests cannot also hide the defect in the product.

**Full-stream malformed/stalled evidence is fail-closed.** Eight evidence forms
(whole-line stall, `error:`-prefixed stall, deadline, valid JSON object, valid
JSON array, two malformed prefix payloads, trailing-comma JSON) are planted 2000
lines past the window — 250x the line bound and ~75x the byte bound — in five
stream shapes, including behind a valid in-window transport or permission
diagnostic, over CRLF, and on a final line with no trailing newline. None yields
a class. Scanner-token loss behind a valid in-window transport diagnostic is
also fail-closed.

The proof is not vacuous: an equally long evidence-free control still classifies
correctly in all four classes, and an implication test pins that everything the
pre-candidate in-window rule rejected is still rejected, so the change can only
be more fail-closed than what it replaced.

**Raw stderr and credentials never enter persistent state.** Five end-to-end
`runTaskVia` runs carry bearer tokens, API keys, a tokenised URL, a passphrase
and a private credential path on stderr. Every file under the state root is read
back and searched for each secret and for every verbatim stderr line. The walk
covers seven files per run — `tasks/`, `events/`, `logs/`, and the
`control/attempts` and `control/transitions` ledgers — and asserts it saw the
task, event and log surfaces, so it cannot silently become vacuous. This is
strictly broader than the candidate's own leak assertion, which reads only the
task and event JSON and never opens the per-task log.

**Zero-semantic non-zero exits stay truthful.** Sixteen exit statuses spanning
1–255, including the shell's 126/127 and the 128+signal range, plus death by
`SIGKILL` (normalised to `exit_status=-1`), each leave the card `held` with
attempts unconsumed, the same writer pinned, no fallback reason, no
resume/backoff, no engine or global cooldown, exactly one product invocation,
and no `retry` or `limit_paused` event. Repeated runs are byte-identical, and
auth/quota precedence is unchanged.

## 5. Findings

No P0 or P1 was found. Three observations are recorded for the reviewer; none
blocks the candidate.

**P3 — the generic process-error path still writes `firstLine(stderr)` into
`res.Result`.** This is pre-existing on `main`, not introduced here, and the
candidate strictly reduces exposure: every stream it now types is redacted to
`exit_status=<n>`, and `combined` is narrowed to stdout so raw stderr cannot
reach the ledger through the limit scanner either. Streams that fail closed
still fall through to the older generic path. Worth a separate look, out of
scope for this change.

**P3 — `grokBuildProcessStderrBoundedLines` splits the entire stderr** with
`strings.Split` before using at most 8 lines, so an 8 MiB stream allocates the
whole slice. Allocation only; correctness is unaffected.

**P3 — the full stream is now walked up to three times** (auth/quota regex,
fail-closed scan, bounded split). Linear and bounded by the same 8 MiB cap, and
the fail-closed ordering is what makes the guarantee sound, so this is the
correct trade.
